# Optional profile vault

The profile vault adds an optional primary password for Nacre's app-owned `settings.json`. That file also contains saved bookmarks and some browser preferences. The vault encrypts the existing profile-integrity envelope with AES-256-GCM and a random data key. A sidecar file, `profile-vault.json`, wraps that data key with a key derived from the user's password using asynchronous scrypt.

The fixed scrypt parameters are N=131072, r=8, p=1, with a 256 MiB maximum allocation bound. Each encrypted record uses a fresh 12-byte nonce, a 16-byte authentication tag, and purpose-bound additional authenticated data. The password is not stored. Password changes rewrap the same data key; they do not rewrite settings. Enabling and disabling use a small journaled file transaction so an interrupted operation is rolled back on the next startup before settings are read.

The module is `src/profile-vault.cjs`. Create it from the Electron main process with the user-data directory. Startup should recover transactions by constructing the module before reading profile files, then prompt for a password and `await vault.unlock(password)` before `readSettings`. Use `vault.isConfigured()` to decide whether the startup unlock prompt is required. The password must be at least 12 Unicode code points and no more than 1024 UTF-8 bytes.

Keep the existing profile-integrity HMAC layer. For the `settings` purpose only, save `vault.seal('settings', profileIntegrity.seal('settings', settings))` when configured, and use `profileIntegrity.open('settings', vault.open('settings', text))` to read a recognized vault envelope. `vault.seal` and `vault.open` are synchronous after unlocking. Legacy-profile detection must inspect decrypted text first. If the vault is configured, a non-vault settings file must fail closed rather than silently falling back to the plaintext profile path. The encrypted envelope can be up to 7 MB because base64 adds space to the 5 MB settings limit.

For enable, pass the freshly generated signed settings envelope to `await vault.enable(password, signedSettingsText)`. For a password change, call `await vault.changePassword(newPassword)` only after the vault is unlocked. `vault.disable()` decrypts and transactionally restores the signed settings envelope, removes the sidecar, and locks the in-memory key. On quit, call `vault.lock()`.

This protects only the current app-owned settings file while Nacre is closed. It does not encrypt Chromium cookies, history, cache, other browser databases, memory, exported bookmark files, prior copies or filesystem snapshots. It cannot protect data while the profile is unlocked from malware running as the same user account. There is no password recovery: losing the password makes the protected settings unreadable.
