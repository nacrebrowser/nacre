Fingerprint: JavaScript, language and time zone

      
Opens browserleaks.com/javascript with Tor active. In the page and iframes, expected: navigator.language en-US, navigator.languages en-US/en, Intl locale en-US, timeZone UTC, Coordinated Universal Time, offset 0, and Date formats in US English. The Chromium smoke confirms Date/Intl/UTC in the three workers tested, but navigator.languages still differs: Worker en-US/fr-FR; SharedWorker and ServiceWorker en-US only. Retest after installation and consider the list of worker languages as a known limit.

Fingerprint: Canvas and Audio

      
Open browserleaks.com/canvas. Partial coverage: OffscreenCanvas, workers and certain frame contexts are not protected. This setting does not certify effective Canvas protection. On supported surfaces, the Canvas hash remains the same when repeating the test in the same domain and session; it should vary on another domain and after restarting Nacre. The mechanism creates a random secret per session, derives it per registrable domain with HMAC-SHA256, and adds deterministic noise to the serialized pixels. Automated tests check simulated buffers, not the score of this third party site; Canvas/Audio/WebGL variations may disrupt applications.

      BrowserLeaks · Canvas ↗
    

    

      
Fingerprint: fonts and PDF plugins

      
Open browserleaks.com/fonts and compare the results with your stable Chrome from the same PC, on the same system profile. Nacre does not forge a PDF list: Chromium itself provides navigator.plugins and mimeTypes, with PDF reader support enabled. Expected result: no Nacre list invented; Values reflect on-board Chromium and may differ from your Chrome. The exact console outputs announced in the request were not included (the received text only contained a placeholder), and therefore were not checked for equality.

      BrowserLeaks · Fonts ↗
    

    

      
Network and HTTPS-only browsing

      
In a new profile, manually enter a known address in http://: Nacre must display the local warning before navigation. Cancel, then choose “Continue Anyway” to check for the one-time exception. An HTTP redirect should also show the warning. With Tor enabled, stop tor.exe: pages should fail and no sessions should return to direct connection. Automated configuration test simulates closed proxy route; only real traffic testing on Windows can verify Chromium processes and transports as a whole.

    

    

      
Fingerprint and User-Agent

      
Open Cover Your Tracks and compare it to real Chrome installed on the same PC. The expected User-Agent is standard Chrome reduced to Chrome/<major>.0.0.0; it must not contain Nacre or Electron. Client Hints should include Google Chrome, formFactors Desktop, and navigator.languages should display en-US then en. PDF plugins now come from the embedded Chromium, not from a list invented by Nacre. Score and uniqueness vary with other features; a good result does not prove anonymity.

Protection regression checklist

      
    
        
  1. Kill switch: Connect Tor, load an HTTPS page, stop tor.exe and reload. Expected result: a Nacre error page or network failure, with no direct access. After reconnecting, the requested page can resume.
    2. 
        
  2. DNS: With Tor connected, test browserleaks.com/dns. Resolvers should not reveal your ISP. Without Tor, Quad9 DoH is used by default, depending on the profile.
    3. 
        
  3. WebRTC: browserleaks.com/webrtc should not show the real IP; RTCPeerConnection may exist. The policy blocks unproxied UDP. Also checks camera/microphone refused without authorization.
    4. 
        
  4. Certificates: Open a test site with an invalid certificate. Nacre should display an error without offering a bypass.
    5. 
        
  5. Tor isolation: Open two private tabs on different domains; each must use separate SOCKS credentials. Close a tab, then use “New Identity”: Tor can create new circuits, but a different exit IP is not guaranteed.
    6. 
        
  6. Permissions: a site that requests a camera, microphone, geolocation or notifications must be refused by default. Check for an “Allow” exception, then reset it.
    7. 
        
  7. Blocker updates: With Tor stopped, updating should fail while keeping the active lists. It must never switch to a direct connection. Each list server receives the request through the Tor exit IP.
    8. 
        
  8. Private browsing: Close the last private tab, then reopen the same site. The temporary session should not reuse cookies or storage. Files you saved remain on disk.
    9. 
        
  9. WebGL: BrowserLeaks must confirm the status described in section WebGL above; this result remains to be verified on the current installation.
    10. 
        
  10. Tor bridges: Choose obfs4 or Snowflake, connect Tor and check its status. If the bridge fails, Nacre should identify the transport and a likely cause. Pages must remain blocked without a direct route.
    11. 
        
  11. Version check: Checks are available only when Tor is connected. GitHub receives the requested repository name and Tor exit address, not your history, bookmarks, or visited URLs. Nothing downloads or installs automatically.
    12. 
        
  12. Bookmarks: Add a bookmark, export it, then import a test file and confirm the result. Non-HTTP(S) URLs should be rejected.
    13. 
        
  13. Downloads: Download a test file and check the sanitized filename and folder choice. An executable must require confirmation before downloading or opening. Nacre pages must not receive the absolute path.
    14. 
        
  14. Filters: Enable the blocker, check its counter and add a site exception. Report a broken site and confirm that the report is copied locally without being sent.
